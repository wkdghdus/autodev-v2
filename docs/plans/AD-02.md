## RALPLAN-DR

### Principles

1. Fail closed when durability, lock ownership, identity binding, or Git side-effect freedom is uncertain.
2. Preserve AD-01 contract boundaries; extend them only where AD-02 needs typed runtime/storage primitives.
3. Record intent before mutation and reconcile uncertainty before duplicate mutation.
4. Keep critical sections short, local, and testable with temporary fixtures.
5. Redact before diagnostics cross module or test boundaries.

### Decision Drivers

1. Fault evidence must directly cover F07 stale preview rejection, F34 idempotency mismatch, F36 interrupted journal/send phases, F38 stale lock evidence, F69 disk/interrupted registry corruption, and F70 passive Git helper side effects.
2. Future milestones depend on these primitives; AD-02 must expose stable APIs without implementing dispatch/provisioning semantics.
3. Implementation must remain stdlib-only and locally reproducible under the repository's existing unittest workflow.

### Options Considered

**Option A: Add a focused `autodev.safety` package and compose it with AD-01 contracts.**

Pros: keeps storage, locks, command runtime, Git reads, and journals isolated; avoids bloating AD-01 validators; lets fault tests target the new primitive layer; allows future milestones to consume explicit small APIs. Cons: creates new modules and integration points that must be documented carefully to avoid becoming a parallel contract system.

**Option B: Fold AD-02 behavior into `autodev.contracts` and existing evidence helpers.**

Pros: fewer new packages and simpler imports. Cons: mixes pure contract parsing with effectful filesystem/process/Git behavior, weakening the AD-01 import-effect guarantee from `tests/test_ad01_effects.py:1-92` and making future effect audits harder.

**Option C: Implement only test fixtures and unsupported stubs now.**

Pros: minimal immediate change and low risk to existing behavior. Cons: fails AD-02's required deliverables in `milestones/AD-02.md:5-20`, leaves future milestones without primitives, and cannot produce meaningful F07/F34/F36/F38/F69/F70 evidence.

**Decision:** Option A.

## Implementation Plan

1. Establish AD-02 safety package boundaries.
   - Add small dataclasses/enums for write recovery status, lock metadata, command request/result, journal load result, and passive Git result.
   - Keep imports stdlib-only and import-safe.
   - If subprocess imports are added, keep them isolated to `autodev.safety.runner`; `tests/test_smoke.py` may allow that exact module import while continuing to block network modules and dynamic import evasions.
   - Acceptance: importing non-runner safety modules and existing `autodev.contracts` under the AD-01 effect guard performs no filesystem mutation, subprocess spawn, or network access; runner import is covered by a separate AD-02 smoke guard.

2. Implement safe storage and shared-map update primitives.
   - Validate an owned safe root before every operation: reject traversal, symlink parents, symlink targets, non-regular targets, unexpected owner ids where inspected, and group/world-writable files or directories inside the trusted root. Do not reject private temporary fixture roots merely because they live under `/tmp`; require the fixture root itself to be private/owned.
   - Use restrictive permissions: `0600` for files and lock records, `0700` for owned directories.
   - Write sibling temporary files in the same directory, apply restrictive permissions, flush/fsync file data, `os.replace` into place, then fsync the parent directory when supported.
   - Treat parent-directory fsync failure as durable-state uncertainty after visibility of the replaced file, not as rollback.
   - Add expected-content/hash compare-and-swap checks using `sha256_bytes` (`src/autodev/evidence.py:30`) without reusing AD-00's allowlisted artifact readers as general storage.
   - Record owner metadata and recovery records separately enough that a partial/corrupt record is recoverable and does not authorize unsafe admission.
   - Acceptance: F07 and F69 tests prove stale previews reject without overwrite, interrupted writes leave parseable old/new state, and corrupt records produce recovery status instead of unsafe writes.

3. Implement lock primitives with documented order.
   - Use stable lock files and fd-held nonblocking `fcntl.flock`.
   - Document and enforce acquisition order as installation -> repository -> account, with same-level locks ordered by canonical identity (`installation_id`, canonical repo identity, then account identity) to avoid deadlocks across shared account maps.
   - Shared-map update sequence must be: acquire stable lock -> read current map -> validate current hash/expected preview -> merge only the addressed project/account key while preserving all other entries -> write sibling temp -> flush/file fsync -> replace -> parent fsync or explicit uncertainty -> release lock.
   - Treat PID, age, and owner metadata as diagnostics only; do not steal ownership without kernel lock release plus generation/process/native evidence. AD-02 only needs kernel lock/record-owner reconciliation; native reconciliation remains future AD-11/AD-12 scope.
   - Acceptance: multi-process contention and stale metadata fixtures cover F38 and prove no blind ownership theft.

4. Implement typed bounded command runner.
   - Accept explicit `argv`, `cwd`, environment allowlist/overrides, timeout, max stdout/stderr bytes, and canaries.
   - Reject shell strings and arbitrary interpolation, following the existing command-validator stance at `src/autodev/contracts/validators.py:733-752`.
   - Use `Popen(start_new_session=True)` on POSIX, bounded concurrent pipe draining, output byte counts before truncation, process-group terminate/kill escalation, child reap, and bounded pipe cleanup.
   - Redact stdout, stderr, exceptions, timeout, overflow, and environment diagnostics before serialization.
   - Acceptance: AC4 tests seed canaries in stdout/stderr/env/error paths and assert no leaks; timeout/overflow tests prove group kill/reap behavior without claiming hostile sandboxing.

5. Implement journal and idempotency registry.
   - Reuse `OperationJournalRecord` and `validate_operation_record` for persisted records (`src/autodev/contracts/model.py:214`, `src/autodev/contracts/validators.py:469`).
   - Define deterministic canonical request bytes/hash for exact supported fields and values: schema version, operation kind, installation id, milestone id, plan digest, grant digest, canonical arguments, idempotency key, owner identity, deployment epoch, and any explicit local mutation target ids. Reject unsupported value types instead of silently stringifying them. Never use `sanitized_json` as the canonicalizer because sanitization can collapse distinct payloads.
   - Bind `operation_id`, `idempotency_key`, `canonical_arguments_digest`, `plan_digest`, `grant_digest`, `installation_id`, `owner_identity`, and `deployment_epoch` together. Same idempotency key with any changed canonical binding rejects and preserves the original identity.
   - Do not persist raw secrets in journal records, canonical request records, diagnostic payloads, or corruption quarantines.
   - Persist PREPARED before any local mutation callback and persist an in-flight/SENT-equivalent state before a callback that may have external/native-style effects. If the callback mutates and the ack/state write fails, load as UNCERTAIN with original operation identity, known durable native ids where present, and explicit `native_ids_unknown`/unknown evidence where not durably known. Corruption or uncertainty must never mint a fresh retry identity.
   - Acceptance: F34 and F36 tests prove same idempotency key with changed canonical payload rejects and crash/load paths preserve intent/native ids conservatively.

6. Implement passive Git inspection adapter.
   - Require a parseable Git version >= 2.36 before repository inspection, since earlier fsmonitor boolean semantics can invoke a hook. Independently gate other required capabilities or refuse their repository modes. Current observed host Git is 2.39.5; tests must cover lower and unparseable versions.
   - Use a clean Git environment: `GIT_OPTIONAL_LOCKS=0`, `GIT_CONFIG_GLOBAL=/dev/null`, `GIT_CONFIG_SYSTEM=/dev/null`, no inherited Git trace/config/env surprises, and `GIT_NO_LAZY_FETCH=1` where supported.
   - Use exact allowlisted commands and flags such as `--no-ext-diff` and `--no-textconv` for diff-like reads.
   - Detect/refuse unsupported repository modes before content reads: external diff, textconv, clean/smudge/process filters, unsafe fsmonitor semantics, lazy-fetch/partial clone uncertainty, and submodule modes unless prevention is proven.
   - Acceptance: F70 marker-helper tests prove helpers are not invoked for supported paths and unsupported configurations fail closed.

7. Add verification evidence and roadmap gate discipline.
   - Add `docs/verification/AD-02.md` only after implementation passes targeted and broad verification.
   - Include changed files, commands/exit codes, AC-by-AC evidence, fault evidence, effect/safety audit, platform boundaries, limitations, and blocked live validation.
   - Do not mark AD-02 complete or AD-03 ready until independent verification exists.

## Deliberate Pre-Mortem

1. A storage primitive reports success after `os.replace` but before parent directory sync succeeds. Mitigation: represent that phase as visible-write-with-durability-uncertain when sync fails, test the failure branch, and avoid promising rollback or universal power-loss durability.
2. A command times out after producing secret-bearing output, and exception formatting leaks the raw buffer. Mitigation: route all result and exception construction through redaction before serialization, test stdout/stderr/env/error canaries, and avoid retaining unredacted payloads in public result objects.
3. A passive Git read invokes a configured helper or lazy fetch through a command variant not covered by tests. Mitigation: exact command allowlist, clean environment, preflight config/refusal checks, marker-helper fixtures, and fail-closed unsupported-mode diagnostics.

## Risks and Mitigations

- Platform filesystem semantics differ. Mitigate by documenting POSIX/local filesystem support, testing the host behavior, and refusing/marking uncertain when directory sync cannot be proven.
- Lock metadata could be mistaken for authority. Mitigate by making kernel lock state and record owner required, with metadata diagnostic only.
- Sanitization could corrupt canonical identity. Mitigate by computing canonical request digests from deterministic unsanitized structural bytes before redaction, and using sanitized forms only for diagnostics.
- Git read commands have hidden helper surfaces. Mitigate by refusing unsupported config/modes and proving supported mode with marker fixtures.
- Existing effect guards block subprocess creation. Mitigate with a narrow AD-02 fixture harness plus a `test_smoke.py` import allowlist for `autodev.safety.runner` only, preserving the network ban and leaving `tests/test_ad01_effects.py` unchanged unless no safer option exists.
- Root path validation can still race against a hostile process changing ancestors between checks. Mitigate by keeping AD-02's boundary to owned trusted roots and descriptor-oriented operations where practical, documenting that this is not a hostile local-process sandbox.

## ADR

### Decision

Implement AD-02 as a focused stdlib-only `autodev.safety` primitive layer composed with AD-01 contracts, plus AD-02 fault tests and verification evidence.

### Drivers

- AD-02 must satisfy storage, locks, command runner, journal, passive Git, and fault evidence requirements from `milestones/AD-02.md:5-20`.
- Shared invariants require fail-closed behavior, deterministic records, and reconciliation before duplicate mutation (`context/SHARED-INVARIANTS.md:5-37`).
- AD-01 import/effect purity must remain protected (`tests/test_ad01_effects.py:1-92`).

### Alternatives Considered

- Fold behavior into `autodev.contracts`: rejected because it mixes effectful primitives with pure schema/contracts.
- Stub unsupported behavior only: rejected because it cannot meet AD-02 deliverables or produce required fault evidence.

### Why Chosen

The safety package gives future milestones reusable primitives while keeping the blast radius narrow, preserving AD-01 boundaries, and giving tests direct seams for fault injection and verification.

### Consequences

- Execution adds several new modules and tests, but the public behavior remains local and fail-closed.
- Supported platform boundaries must be documented honestly.
- Future dispatch milestones can consume journal/idempotency primitives but still need their own native reconciliation semantics.

### Follow-Ups

- After implementation, write `docs/verification/AD-02.md`.
- Advance `ROADMAP.yaml` only after independent verification.
- Future AD-05/AD-11/AD-12 should extend native capability, reconciliation, and dispatch semantics without weakening AD-02 primitives.

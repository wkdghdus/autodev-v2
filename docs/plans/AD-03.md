# AD-03 implementation plan — conservative repository alignment

Status: consensus approved by independent Architect and Critic reviews after revision 1; planning only. Authority: `milestones/AD-03.md` and `context/SHARED-INVARIANTS.md`. This is the single canonical implementation plan; OMX handoff documents reference it. Preserve the current uncommitted AD-02 work. Do not change roadmap state during planning. Consensus approval approves the plan's quality, not product authority or execution enablement.

## Objective, scope and exclusions

Implement `autodev init <repo>` as bounded, passive discovery followed by a reviewable, explicitly applied repository alignment proposal. Empty/incomplete repositories get honest AD-01-valid drafts; existing contracts and source artifacts retain their exact bytes. Ambiguity and unsupported safety states produce explicit diagnostics instead of guesses.

Scope: discovery of context, requirements, execution maps/roadmaps, plans, acceptance artifacts and toolchain metadata; declared-context reads and recognition diagnostics; deterministic preview/JSON; missing draft files; minimal verified ignore repair for an explicitly identified in-repository managed worktree bucket; repository byte writes, recoverable transaction records, CLI and fixture/effect tests.

Excluded: compiling roadmaps into milestones, importing approvals, setting `configured`, enabling execution/lifecycle, running hooks/scripts/toolchain commands, models, MCP, profile configuration, installation binding, commits, creating worktrees, migrating unsupported YAML, general YAML editing, initial commits, AD-04 compiler/approval functionality, new dependencies. Discovery identifies references and evidence only; generated configuration never approves authority. `PRODUCT.md:36–52,90–97` defines this alignment boundary.

## RALPLAN-DR

Principles:

1. Preserve user bytes, explicit references and authority boundaries.
2. Passive reads are bounded; ambiguity and missing proof fail closed.
3. Every write belongs to an exact reviewed proposal and recoverable transaction.
4. Identical inputs yield identical proposals, and aligned reruns have zero writes.

Top three drivers: AD-03 AC2 byte identity; AC1/F05 honest draft authority; AC4/F67 effects confinement.

Options:

- **A — create missing contracts, preserve existing contracts wholesale (chosen).** Existing valid contracts are never rewritten; unsupported/invalid partial documents receive precise NEEDS_INPUT. Missing peer files can be generated using existing project identity and references. Pros: small diff, strongest byte guarantee, no YAML writer framework. Cons: malformed or partially populated existing contract files may need manual correction before alignment; explain exactly which field blocks progress.
- **B — surgical byte-span updates to existing YAML.** Add a restricted token/span scanner and patch only missing fields, preserving remaining ranges. Pros: more incomplete documents repair automatically. Cons: quote/indent/newline ambiguity, overlapping replacements, larger parser maintenance surface. Viable for later explicit demand; unnecessary to satisfy incomplete-repository discovery and missing-file drafts now. Unsupported structure must still fail closed.
- General YAML reserialization is invalid here: existing parser drops comments and no dependency is authorized. Silent selection of the first discovered roadmap is invalid because it violates AC3/F04.

## Behavior and implementation decisions

### 1. Bounded discovery and precedence

Enumerate with streaming `os.scandir`: count each encountered entry before buffering it, stop at the shared bound, and sort only the bounded buffer; never `list`/sort an unbounded directory. Use deterministic sorted traversal with explicit constants: depth at most 4 from each selected root, at most 2,000 directory entries total, at most 200 candidate files, at most 128 KiB per content read and 4 MiB aggregate content bytes. Enforce counters before opening/descending; classify an oversized candidate as unreadable and return NEEDS_INPUT if relevant, never silently truncate evidence. Hitting any enumeration/aggregate limit reports `discovery_limit` and forbids apply. Explicit references consume the same budget; allow a selected exact reference beyond traversal depth without traversing extra directories. No symlink following, special-file reads, hidden-directory blanket recursion, shell sourcing or imports. Reject symlinked root, symlink components, escapes, hardlinked mutation targets and casefold collisions; paths with spaces/Unicode are literal argv/data. Skip `.git`, `.agent/.init-state`, dependency/build/cache directories (`node_modules`, `.venv`, `venv`, `dist`, `build`, `__pycache__`) and selected managed bucket. Other hidden roots require explicit selection.

Search repository root plus literal `docs`, `context`, `requirements`, `plans`, `milestones`, `tests`, and `test` directories when present, subject to the shared budget; also bounded explicit `sources.discovery.roots`. Categories are a documented finite registry, tested with positives and negatives: context `AGENT.md`, `AGENTS.md`, `CLAUDE.md`, `GEMINI.md` and Markdown under context roots; requirement names `PRODUCT`, `PRD`, `REQUIREMENTS`, `SPECIFICATION`; execution `ROADMAP` plus `.agent/EXECUTION.yaml`; plan files under `plans` or `docs/plans`; acceptance `ACCEPTANCE`, `ACCEPTANCE-CRITERIA` and test-file inventory; metadata `pyproject.toml`, `package.json`, lockfiles, `Makefile`, and test configuration names. Text artifact suffixes: `.md`, `.yaml`, `.yml`, `.json`, `.toml`, `.txt`; matching uses casefolded basenames but path collisions block. Toolchain fields are static suggestions, not commands to execute or automatically authorized verification entries. Read only bounded known data; malformed metadata stays an unreadable diagnostic.

PROJECT discovery is separate from artifact ranking: inspect bounded exact conventional paths `PROJECT.yaml` and `.agent/PROJECT.yaml` before deriving identity. `--project <repo-relative-path>` explicitly selects a custom existing PROJECT or a missing destination; apply the same path/read bounds. If multiple existing conventional PROJECT files exist and none was explicitly selected, return NEEDS_INPUT with exact `--project` choices, even if their UUIDs agree. A custom selection must not silently duplicate a different conventional existing identity: surface the conflict and require operator reconciliation. Missing default destination does not authorize creating a second PROJECT when an existing recognized/custom-selected PROJECT is present. Do not search arbitrary filenames for PROJECT or guess custom paths; report this bounded recognition scope.

Precedence: valid existing explicit PROJECT reference > explicit operator selection for an otherwise unset field > sole eligible discovered candidate > unresolved. Never replace/remove an existing reference because a candidate scores higher; missing/malformed/out-of-root source/context/acceptance references block that field and request repair. Exception: an absent declared `sources.execution_index` is a missing alignment destination, so create its empty peer at that exact safe path after preview; an existing malformed index still blocks. It is never substituted by the default path. Do not offer CLI overrides of existing nonempty references in AD-03. No fuzzy scoring or filename-order tie-break. Multi-valued context/requirements can be selected together only when each is directly declared or explicitly selected; multiple plausible authority artifacts require a choice and cannot become implicit joint authority. Roadmap/plans are candidates, not execution items. Selection cannot promote draft authority or alter existing approval records.

Provide repeatable `--select <category>=<relative-path>` for unresolved choices. TTY text mode may ask a bounded numbered choice; cancellation/EOF leaves NEEDS_INPUT. Non-TTY/JSON never prompts or guesses. `--yes` cannot resolve a tie. Discovery diagnostics show candidates and exact selection syntax.

### 2. Drafts and source preservation

AD-03 design choice (not an inherited contract requirement): after conventional/custom detection above proves no existing selected PROJECT, default absent PROJECT destination is `.agent/PROJECT.yaml`; `--project` selects an explicit alternative; existing explicit execution-index path governs the missing EXECUTION destination, otherwise `.agent/EXECUTION.yaml`. If default PROJECT already exists, validate it without changing bytes. If only an existing EXECUTION exists, its validated UUID may seed the missing PROJECT; inconsistent/malformed peer identity is NEEDS_INPUT. Do not overwrite a pre-existing target, including empty files, directories or links. Existing partial/malformed PROJECT or EXECUTION returns field/path diagnostics and no write; this is an explicit unsupported repair boundary, not invented content. Existing configured PROJECT can receive its missing empty index only if validation and existing contract semantics permit it; never downgrade PROJECT or fabricate milestones.

Use a small deterministic renderer for **new files only**, quoting strings with a safe supported subset. Include only contract-required defaults: schema v2, `setup_state: draft`, derived human label/valid slug, `gajae`/`approved_roadmap_only`/`dependencies_integrated`, null target, limits 1, independent review true, empty command list, empty requested-authority map, and empty milestones. Unique/selected references may populate the draft source lists; absent evidence stays empty with diagnostics. No PRD, milestone, approved plan, approval receipt, installation or product authority is generated. Plans/roadmap candidates remain report data. Validate proposed pair through AD-01 before allowing apply.

Preserve existing UUID; for a new pair derive UUID5 in a fixed AutoDev-init namespace from canonical repository realpath and ordinary Git common-dir realpath (or explicit non-Git marker). This is a stable draft identity for unchanged local inputs, never a global clone identity or installation binding. After creation UUID is authoritative and survives relocation; moving between preview/apply invalidates the proposal. No time, randomness or process generation enters proposal JSON or new YAML. Expose `--name <text>` and `--slug <valid-slug>` only for newly generated PROJECT display metadata. Empty/colliding/invalid derived slug gives NEEDS_INPUT with these exact flags. Validate with AD-01; reject attempts to alter existing PROJECT display metadata with `existing_project_metadata_immutable`. Neither flag changes identity derivation or resolves a competing PROJECT.

Round-trip repository byte support means an unchanged existing file returns its original byte buffer, and a reviewed `.gitignore` append preserves its entire original prefix, newline style and file mode. It does not mean a general YAML formatter. Support CRLF, trailing comments and missing final newline without altering original bytes; append a separator only when needed. Existing source artifacts are read-only.

### 3. Preview, apply and deterministic JSON

CLI contract (new AD-03 choices): `autodev init <repo>` previews; `--dry-run` makes the no-write contract explicit; `--json` emits one canonical JSON object; `--yes` permits applying only after the exact preview has been emitted in the same interactive/text invocation. A separate noninteractive workflow is preview to caller-owned output, then `--apply <proposal-digest> --yes` with identical selection arguments; it recomputes and compares the proposal digest before applying. That prior digest-bound preview supplies the review step. Text mode may stream the recomputed proposal before mutation. JSON apply emits exactly one final canonical envelope containing both the recomputed reviewed proposal and outcome (including failure/stale/recovery status); it never writes a preliminary JSON object followed by a second result. `--dry-run` conflicts with apply/yes mutation intent. JSON preview alone always writes zero files; JSON apply requires explicit digest and yes. No auto-saving preview files and no write implicit in `--yes` without an emitted preview. A TTY may confirm apply after preview; EOF declines. This is consent to exact alignment bytes only, never product authority.

Use exit 0 for successful preview/no-op/applied, 2 NEEDS_INPUT or unsafe/unsupported inputs, and 1 controlled operational failure or recovery conflict; JSON status distinguishes `preview`, `noop`, `applied`, `needs_input`, `failed`, `recovery_required`. Stable ordered fields/arrays and reason codes; no timestamps, absolute temp paths, unstable error strings, observed process IDs, volatile stat times or secrets. Apply result may differ in status, but repeated same-mode unchanged-input JSON is byte-identical. Include `setup_state`, `lifecycle_ready: false`, candidates, declared-context read results, unresolved choices, exact file operations, before/after hashes and write/effect summary. Redact unsafe diagnostic content through existing helpers; do not dump source bodies or environment.

Digest canonicalizes schema/version, canonical repo/common-dir identity, Git state/revision if available, explicit selections, existing project identity, complete bounded discovery inventory and relevant contents (including ignore/config/index-derived evidence), all target original hashes or absence, proposed bytes/hashes, and finite alignment operations. Hash inventory names plus candidate content so an added competing roadmap invalidates old preview. Validation limits/registry version are bound too. Ignore the tool's excluded private state in discovery; no-op outcome is stable after apply. Revalidate all premises under lock before first write. Unrelated file changes need not block unless included in the bounded discovery inventory; state exactly which evidence is bound. Missing/changed target, new competing candidate, changed explicit reference or stale Git evidence => stale proposal, zero alignment-file writes. Pre-lock pure stale checks write nothing; a race detected after apply-only bootstrap/lock may leave only the previously disclosed private state/lock artifacts, which the final effect summary must distinguish from alignment changes. Never describe that latter outcome as globally zero writes. Read-only preview must not instantiate SafeStore, FileLock, mkdir, temporary write, profile access, pycache writes or mutation recovery.

### 4. Git states, managed bucket and ignore repair

Keep AD-02 preflight rejection of linked worktrees, `.git` files/symlinks, submodules, filters/fsmonitor/helpers/includes, partial clones, alternates and unsupported extensions. Non-Git directory and unborn ordinary repository may get draft alignment with `lifecycle_ready: false`; no initial commit or readiness claim. Bare repositories are explicitly rejected. Detached ordinary HEAD may be passively aligned with diagnostic; dirty repositories may align only reviewed paths with content preconditions, never stage/stash/reset/commit. An existing destination changed by the operator remains a conflict. Corrupt/ambiguous Git metadata is rejected, never mislabeled unborn.

Extend `git_read.py` with typed, fixed-argv reads only: bounded tracked-index membership under one validated bucket (`ls-files --cached --full-name -z -- <literal-bucket>`), ignore queries (`check-ignore --no-index` with NUL-safe arguments/results), and narrowly scoped HEAD/symbolic-ref classification if required. Preserve sanitized environment, no pager/diff/textconv, no shell, output/timeout bounds and existing preflight. Result adapters must model check-ignore exit 1 as a valid negative observation and exit 128/overflow/truncation as unknown/blocker. Verify semantics against official docs before implementation: [ls-files](https://git-scm.com/docs/git-ls-files), [check-ignore](https://git-scm.com/docs/git-check-ignore), [gitignore](https://git-scm.com/docs/gitignore), [rev-parse](https://git-scm.com/docs/git-rev-parse), [symbolic-ref](https://git-scm.com/docs/git-symbolic-ref). Failed HEAD verification alone does not prove unborn; require consistent symbolic branch and absence evidence or reject uncertain state.

No bucket convention is established in current contracts. Use explicit `--worktree-bucket <repo-relative-directory>` or an unambiguous static existing metadata hint shown in preview; absent/ambiguous strategy remains `unknown`, allows unrelated drafts but never readiness. Existing Git linked-worktree metadata is unsupported, not inferred as permission. External/sibling strategy is reported only, without external writes. Reject bucket escape/symlink/newline/NUL/glob/metacharacter ambiguity and overlap with `.git`, `.agent`, discovery roots/contract targets; require a literal path representable by one anchored gitignore rule. Any indexed path under the bucket, including staged/deleted entries, blocks lifecycle and ignore repair; do not delete/untrack. Report exact paths under output bounds.

For known safe in-repo bucket, propose at most appending `/<escaped-literal-bucket>/` at end of root `.gitignore`, preserving bytes. Existing root exclusion may already suffice; use real Git ignore observations and source/pattern provenance. Do not call one ignored sentinel proof for arbitrary descendants. Require effective exclusion of the bucket directory itself and all bounded known descendant probes, understand root/nested negation precedence, and report the proof scope. A directory-level anchored last rule excludes traversal; if input semantics cannot establish that exclusion (negations/unsupported encoding/limits), return NEEDS_INPUT instead of claiming a verified repair. Perform post-write passive checks; failure rolls back owned edit. Never invoke Git worktree/index mutations. Private init-state is separate from managed bucket policy and is not lifecycle readiness evidence.

### 5. Ordinary repository writes and transaction safety

Add `src/autodev/safety/repository_files.py` for byte-preserving repository targets, separate from SafeStore. It accepts only exact reviewed relative paths, root descriptor/component checks, regular non-symlink single-link targets, immutable original/proposed bytes and expected absence/hash. Preserve existing mode; create normal repository files with restrictive baseline compatible with repository ownership, not forced SafeStore ownership on user directories. Stage same-directory files and fsync. For expected-absent destinations use an atomic no-clobber publish primitive (for example descriptor-relative hard-link publication of the staged regular inode, failing EEXIST, followed by unlinking only the owned staging name), not existence-check plus rename/replace. If required primitives are unavailable, reject before alignment changes. Existing-file replacement uses atomic rename only after expected hash **and device/inode identity** recheck. The stable lock serializes cooperative AutoDev writers; it does not provide compare-and-swap against arbitrary external writers. State this limit in evidence; do not claim protection against arbitrary writes between final recheck and rename. Refuse observed external changes. Directory fsync follows publish; use descriptor-relative/no-follow operations where available. Reject unsupported filesystem primitives rather than weaken safety. Never chmod an existing user directory to 0700. New parents are reviewed operations and removed on rollback only if still tool-owned and empty.

Apply-time private `.agent/.init-state` (0700, owned JSON records 0600) is explicitly disclosed in preview, excluded from discovery, never used for PROJECT/EXECUTION serialization. Reject an existing unowned/unsafe/linked/tracked state path. Reuse SafeStore for durable transaction intent/original byte records (base64 plus hashes), and stable AD-02 repository lock. Metadata records are tool-owned apply effects distinct from alignment files; do not add a global/home/profile root. If private state cannot safely be created, return NEEDS_INPUT. Keep successful records durable for recovery evidence; aligned no-op must neither construct locks/state nor update records. Bootstrap protocol: after explicit apply and pure preconditions, create the exact reviewed `.agent` parent only if absent using exclusive mkdir; preserve existing parent mode/ownership. Create `.agent/.init-state` with exclusive mkdir(0700), then create `owner.json` with O_CREAT|O_EXCL|O_NOFOLLOW (0600) containing schema, a fixed AutoDev-init owner marker and canonical repository-root identity, fsync file and directory. The repository lock key is SHA256 of canonical repository root identity alone (not project UUID, selected PROJECT path or slug); it is stored at a stable name under this root and is never unlinked/replaced, including rollback/shutdown. Concurrent process encountering an existing state root must wait/retry only a bounded bootstrap interval, validate completed owner record/root identity, and then contend on the same lock. Preexisting ownerless/malformed/foreign state cannot be adopted automatically; report `bootstrap_recovery_required`, no alignment edits, and an exact diagnostic. A crash between mkdir and owner publication therefore fails closed rather than silently taking ownership. Valid matching state may be reopened; all transaction recovery runs under its stable lock. Preview inventories exclude the private state tree and newly created empty `.agent` container as infrastructure-only observations; binding still includes every concrete `.agent` candidate/target and original target absence, so bootstrap cannot invalidate its own proposal or hide a competing artifact. No clean-state assertion may be inferred from lock availability.

Before first alignment replacement, persist/fsync one transaction manifest containing exact reviewed destinations, original bytes or absence, modes, new bytes/hashes, identity and parent ownership. Then apply in deterministic path order, checkpoint after each durable replacement, verify full pair/ignore evidence, mark committed. Multi-file atomicity is **not** claimed. Ordinary exceptions roll back owned replacements in reverse order only where current bytes still equal transaction-written bytes **and device/inode identity matches the recorded published inode**; preserve external edits and report `recovery_required` on any mismatch. A user replacement with identical bytes but a different inode is a recovery conflict and must survive rollback. Remove newly created files only if unchanged in bytes and inode; never delete existing source artifacts. Record uncertain operations for reconciliation rather than duplicate replay. On subsequent invocation preview reads pending intent without writes and reports recovery required. Explicit `--recover --yes` first presents the bounded recovery diff, locks and restores only provably owned bytes under the same rules; it cannot simultaneously apply a new proposal. Recovery conflict requires manual resolution and never overwrites a changed file. Faults after intent/before replacement/after replacement/before commit and concurrent init processes are mandatory tests. Kernel lock release alone never proves clean state. Retained metadata and lock files are disclosed local artifacts, not product authority.

## ADR

Decision: implement passive bounded discovery, immutable existing contracts, create-only draft rendering, one exact preview/apply binding and recoverable ordinary repository byte writes. Drivers: preserve bytes and authority; keep effects local/explicit; deterministic review and safe recovery. Alternatives considered: restricted YAML span editing (viable, more automatic but larger risky surface), general reserialization (violates byte constraints), automatic roadmap inference (violates ambiguity/authority). Why chosen: smallest implementation meeting current milestone without a parser framework or future compiler. Consequences: malformed partial contracts need correction; unsupported Git/filesystem states reject; multi-file alignment can temporarily be partial and is reconciled before reuse; private recovery artifacts are disclosed apply-time effects; draft UUID scope is local until persisted.

## Effect and safety audit

All tests operate in temporary roots. Only the typed runner imports subprocess in the package. Commands receive explicit argv, cwd and environment; `shell=True` and shell string interpolation are absent. Concurrent stdout/stderr reads use nonblocking selectors, retain only configured byte limits, count observed bytes before truncation, and stop/reap the owned group on timeout or overflow. SIGTERM-resistant descendants and descendants keeping inherited pipes after parent exit are exercised.

Owned roots and components reject symlinks, traversal, unexpected uid, nonregular targets and group/world-writable metadata before content access. New owned directories are 0700; target, temp, recovery and lock files are 0600. Locks retain stable inodes. Acquisition order is installation → repository → account; same-level identities sort canonically and release reverses acquisition. Internal per-target storage locks sit inside the application lock and never acquire another application lock.

Journal files contain validated AD-01 `OperationJournalRecord` data plus digests of canonical arguments, local target IDs and immutable identity bindings. Raw arguments and secret canaries are not persisted, even when arguments contain secret-bearing keys. Secret-bearing persisted identity/native-ID values refuse. Canonical identity never uses sanitized JSON. Corrupt identity hints are sanitized diagnostics with `CORRUPT`, not authority. PREPARED/SENT/uncertain or already acknowledged operations cannot replay effects through `run_with_journal`.

Git requires a parseable version >=2.36 before repository inspection. A non-executing `git config --local --null --list --no-includes` preflight rejects hidden include/helper/partial-clone modes. Supported reads use a clean environment, disabled optional locking/fsmonitor/untracked cache, no pager, no external diff/textconv and ignored submodules. `GIT_NO_LAZY_FETCH` is defense in depth; safety on Git 2.39.5 does not assume support for that variable because promisor/alternate modes are refused independently.

## Recovery APIs and limits

`SafeStore.recover` exposes visible content, digest, status and admission. `reconcile_write` explicitly syncs a recognized old/new record before allowing another write; it never repairs corruption. `expected_hash=ABSENT` represents a missing-file preview; omitting an expected hash performs a serialized unconditional replacement. `SharedJsonMap.update_key` holds the application lock and the target transaction across the merge.

Supported evidence is POSIX/local filesystem behavior on this macOS host, Python 3.14, Git 2.39.5 (Apple Git-154). Python project minimum remains 3.11. Directory fsync is verified on temporary host storage only; unsupported/failing sync remains uncertainty. No universal power-loss durability, network-filesystem locking, hostile local-process containment, or Windows support is claimed. Escaped process groups are outside the runner boundary; bounded pipe cleanup discards incomplete output. Captured byte counts cover bytes observed before cleanup, not output an already terminated process would otherwise produce.

Passive Git supports ordinary local repositories and the exact status/show operations only. Linked worktrees, includes, submodule/partial-clone/alternate modes are conservative refusals, not unverified support. No runtime provisioning, native provider reconciliation, dispatch, account/budget admission, scheduler, live network service, real broker or credential database was exercised. Those validations belong to later milestones.

## Binding, crash, concurrency and ownership audit

The independent module contains 22 tests. It uses actual files and separate interpreter processes rather than substituted transaction results:

- `os._exit` at bootstrap-directory, durable-intent, before-publish, after-publish, after-file-checkpoint, before-commit and after-commit boundaries; pending previews remain read-only, explicit recovery restores owned edits, and committed transactions remain committed.
- Actual death after staging-file creation but before recording its inode, and after parent mkdir but before recording its inode. Uncertain retained artifacts require reconciliation; recovery cannot report clean while silently leaving an unowned orphan.
- Death during restoration of an existing `.gitignore`, followed by idempotent recovery of exact original bytes and mode.
- Concurrent processes overlap a durable pending transaction. Exactly one alignment applies; the other refuses/stales, and one stable repository lock remains.
- An external creation wins the expected-absent race without being overwritten. An identical-byte replacement with a new inode survives rollback/recovery as a conflict.
- External staging-byte corruption is detected before destination publication. Changed staging data is not promoted to reviewed alignment bytes.
- Actual directory swaps to outside symlinks during staging and bootstrap never write into the outside destination.
- Changed declared-reference bytes invalidate the reviewed digest before state bootstrap. Executor tests add new-candidate, target and Git-evidence binding, late stale outcomes with disclosed infrastructure effects, link-publication interruption and shared canonical-root lock identity.

Fault injection intercepts individual low-level calls but performs real mkdir/open/replace/write operations and process termination; assertions inspect the resulting filesystem. It is simulated interruption evidence, not a power-loss or live-runtime claim.

## Effect boundary and known limitations

- Preview/dry-run never constructs locks, private state, temporary repository files or recovery writes. Apply effects are exact reviewed alignment paths, reviewed parents, same-directory staging files, and disclosed `.agent/.init-state` ownership/manifest/stable-lock records. Late stale detection can retain disclosed private infrastructure while making zero alignment changes.
- Existing-file rename and rollback provide checks under a cooperative AutoDev lock; they are not compare-and-swap against an arbitrary external writer between the last check and rename. Multi-file atomicity is not claimed.
- Bootstrap and repository target operations use descriptor-confined traversal. Once the owned private state is established, inherited AD-02 SafeStore/FileLock assumes its private root is not concurrently replaced by a hostile local actor. This is an explicit private-state trust boundary.
- A bootstrap crash before owner publication and an unrecorded staging/parent inode fail closed; manual reconciliation may be required. Foreign/malformed/unsafe state is never adopted. Retained state/locks are local recovery evidence, never approval authority.
- JSON recovery returns `recovery_text_review_required` and performs no writes; text recovery presents the recovery diff before mutation. JSON apply emits one envelope. Public previews redact secret-bearing display values and show only the added suffix for append operations, while exact internal byte hashes remain bound.
- Existing malformed/partial YAML repair is unsupported; existing bytes are not rewritten. Unsupported Git/filesystem states are rejected. Host-global ignore settings are intentionally excluded from repository proof. Discovery/ignore evidence is bounded; exceeding bounds blocks instead of claiming completeness.
- The observed platform supports POSIX descriptor-relative, no-follow, link, flock and fsync primitives. Other platforms/filesystems and actual power loss were not tested. No live models, MCP servers, lifecycle execution, product compiler or runtime context ingestion were invoked; ingestion remains unverified by design.

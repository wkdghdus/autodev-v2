## Effect audit and actual call paths

The harness launches one fixed local Python script using an absolute interpreter,
no shell, disabled bytecode, temporary HOME/XDG_CONFIG_HOME/cwd and a minimal
environment without inherited credentials. Its audit hook is installed before
AutoDev imports. Reads are bounded to reviewed source/evidence/fixture/stdlib
roots and temporary provided/protected data; writes are bounded to owned and
provided temp directories. Descendant process and socket events are denied.
The fixed parent launch is test infrastructure, not app dispatch.

An independent direct guarded-child run exited 0: two allowed temp writes
(provided canary input, sanitized report), two denied protected writes (Path and
os.open), one denied read, two denied processes (Popen and os.system), two denied
network attempts (socket and connection). All seven controls were observed;
Nous/Hermes/GJC/cron/account sentinel snapshots were unchanged. Sources=3,
inputs=8, fixtures=6; help/module help=0; all six future commands=2. Report/audit
output contained no canary. Hash-error text was the fixed sanitized message.

Actual source review: __init__ defines version; __main__ invokes argparse CLI;
CLI only parses/prints. Evidence imports define functions/constants without
reads; JSON/hash helpers validate artifact roots/static inputs; provided reads
require explicit roots and expected hash. Raw parent symlink checks precede
reads. Sanitizer transforms data in memory, redacting keys, assignments,
plain/Basic/Bearer authorization, URL userinfo, private keys and explicit
canaries. No app subprocess/socket/service dispatch, credential traversal or
production write path exists. This call/alias inspection supplements the AST
import check.

Initial review rejected unguarded imports/children, unrestricted helpers,
inadequate tamper proof, authorization leakage and parent-symlink handling.
These were corrected; fresh independent tests include no-canary authorization
regressions and parent-directory symlink rejection.

## Limits and blocked live validation

Sentinels are synthetic local evidence, not measurements of production/remote
account state. The audit hook is a bounded regression guard for reviewed Python
paths, not an arbitrary malicious/native-code sandbox. Startup/stdlib activity
and test infrastructure are outside app-path proof. No race-resistant filesystem
sandbox is claimed. Provided roots are explicit caller authority inputs; trusted
system aliases above those roots are allowed. Redaction covers tested forms and
explicit canaries, not every encoded secret representation.

S1–S3 bodies remain unavailable. Real traces and live Nous/Hermes/GJC/runtime,
provider, credential, billing, MCP, broker, scheduler and account validation
remain UNKNOWN/BLOCKED_EXTERNAL/UNSUPPORTED. AD-00 authorizes no live probes;
later scoped authority/evidence is required. Missing/synthetic results never
become live PASS.
